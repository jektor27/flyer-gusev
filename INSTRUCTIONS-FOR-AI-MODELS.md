## 3. Критично: как публиковать изменения

GitHub Pages обновляется **только после push**. Локальные правки пользователь не видит.

```bash
cd D:\Jastas\projects\flyer-gusev
git add -A
git commit -m "fix: короткое описание"
git push https://jektor27:<TOKEN>@github.com/jektor27/flyer-gusev.git main
```

> ⚠️ `<TOKEN>` — персональный токен GitHub (PAT) пользователя. Токен живёт **только в памяти ассистента/окружении**, в репозиторий его писать ЗАПРЕЩЕНО — GitHub блокирует push с секретами (push protection). При публикации замените `<TOKEN>` на актуальный токен.
> После пуша CDN GitHub Pages отдаёт свежий файл не сразу — проверять онлайн лучше через 30–60 секунд и с параметром кэша (`?v=<timestamp>`).

### Локальная проверка
```bash
python -m http.server 8765 --directory D:\Jastas\projects\flyer-gusev
```
Затем открыть `http://localhost:8765/index.html` в Playwright/браузере. После проверки сервер остановить (найти процесс: `Get-NetTCPConnection -LocalPort 8765 -State Listen`).

## 4. Архитектура и ключевые правила

### 4.1. Единая шапка и подвал
- Шаблон живёт в **`navigation.html`** — это НЕ страница, это фрагмент для копирования.
- На каждой странице шапка и футер должны быть **одинаковыми** и совпадать с `navigation.html`.
- Шапка: `<header class="site-header">` → `.container` → `.logo` (иконка ФГ + текст «Флаер**Гусев**») + `nav.nav` (5 ссылок: Главная, Категории, Тарифы, Блог, Контакты) + `button.menu-btn` (бургер).
- Меню сворачивается в бургер на `max-width:1140px` (CSS в `style.css`), переключает `js/main.js → toggleMenu()`.
- ⚠️ **Запрещено** делать шапку «своей» на отдельной странице (inline-шапка с `nav.main-nav` без бургера). Из-за этого уже был баг: логотип прилипал к «Главная», не было адаптива.

### 4.2. Логотип и фавикон (текущий дизайн)
- Лого-иконка: **буквы «ФГ»** — «Ф» белая `#ffffff`, «Г» красная `#e94560`, на тёмно-синей плашке `#16213e` (CSS-класс `.logo-icon`).
- Inline SVG (вставляется в каждую страницу в `.logo-icon`):
```html
<svg viewBox="0 0 100 100" width="34" height="34" aria-hidden="true"><text x="36" y="54" font-family="Segoe UI, Arial, sans-serif" font-size="72" font-weight="900" fill="#ffffff" text-anchor="middle" dominant-baseline="central">Ф</text><text x="83" y="54" font-family="Segoe UI, Arial, sans-serif" font-size="72" font-weight="900" fill="#e94560" text-anchor="middle" dominant-baseline="central">Г</text></svg>
```
- Файлы фавикона: `favicon.svg` (исходник), `favicon.png` (32×32), `favicon.ico` (16/32/48), `apple-touch-icon.png` (180×180). Ссылки на них прописаны в `<head>` всех страниц.
- ⚠️ Не заменять логотип на эмодзи (🫎/📋) — это был провал №1: эмодзи превращается в «иероглиф» на 16px.
- ⚠️ Если модель умеет видеть изображения: перед генерацией логотипа читайте файл `DESIGN-BRIEF-FAVICON-LOGO.md` в корне проекта и показывайте эскизы пользователю на согласование.

### 4.4. Данные магазинов — единый источник
- Вся информация о магазинах и категориях — **в `js/main.js`** в константах `shopsData` и `categories` (массивы/объекты с id, названиями, адресами, телефонами, описаниями, продуктами, рейтингами, категориями).
- ⚠️ Добавлять/менять магазин ТОЛЬКО в `shopsData`. Отдельные страницы категорий читают эти же данные (или генерируются из них).
- Есть генератор страниц `create_landing_pages.py` — если меняется разметка карточек, им удобно пересобирать.

### 4.5. «Популярные запросы» на главной
- Сортировка по просмотрам категорий, хранящимся в **localStorage** (`flyer_cat_clicks`).
- Функции в `js/main.js`: `getCategoryClicks`, `registerCategoryClick`, `loadPopularQueries`.
- Не удалять localStorage-логику — это осознанная фича.

### 4.6. Рейтинг магазинов
- `rating` в `shopsData` — рейтинг, показываемый на карточках. Не «живой», а редактируемый вручную.
- Карточки могут подсчитывать клики по магазинам (есть функция рейтинга по кликам — проверяйте, что она не конфликтует с ручным рейтингом).

## 6. Типичные задачи и как их делать

1. **Починить вёрстку/шапку** → сверить страницу с `navigation.html`, поправить, проверить на 4 ширинах (1280 / 1140 / 800 / 400) через Playwright, проверить, что на ≤1140px меню сворачивается в бургер и нет горизонтального скролла.
2. **Добавить магазин** → добавить объект в `shopsData` (js/main.js), проверить отображение на главной и в категории, задеплоить.
3. **Поменять фавикон/логотип** → изменить `favicon.svg`, сгенерировать PNG/ICO (рендер SVG через Playwright → Pillow), обновить inline SVG во ВСЕХ html (и в `create_landing_pages.py`, и в `blog/*.html`), проверить читаемость на 16px.
4. **SEO** → для продвижения личного бренда «Пряжников Александр Иванович» есть отдельные файлы `SEO_DICTIONARY.md`, `sitemap.xml`, `robots.txt`; следовать им.

## 8. Частые ошибки прошлых сессий (НЕ повторять)

1. Эмодзи в качестве фавикона/логотипа → «иероглиф» в вкладке браузера.
2. Своя шапка на одной странице вместо общей → разъезд логотипа и меню, нет бургера.
3. Замена во всех HTML, кроме `blog/*.html` и `create_landing_pages.py` → остаются старые иконки.
4. Проверка только локально, без пуша → пользователь не видит результат.
5. Правка данных магазинов в разметке страниц вместо `shopsData` → рассинхрон.
6. Проверка кэшированного онлайн-файла → видно «старую» версию, хотя push прошёл.
